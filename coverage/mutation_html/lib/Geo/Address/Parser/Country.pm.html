  142: =head1 DESCRIPTION
  143: 
  144: Resolves the last comma-separated component of a place string into a
  145: canonical country name. Handles common variants, abbreviations, and
  146: historical names found in genealogy data and other poorly-normalised
  147: address sources.
  148: 
  149: Designed specifically to tolerate poor-quality data from software
  150: imports where place strings may be inconsistent, abbreviated, or use
  151: historical country names no longer in common use.
  152: 
  153: Resolution proceeds through the following steps in order:
  154: 
  155: =over 4
  156: 
  157: =item 1. Direct lookup table (covers historical names, abbreviations,
  158: common variants)
  159: 
  160: =item 2. US state code or name via Locale::US
  161: 
  162: =item 3. Canadian province code or name via Locale::CA (English and French)
  163: 
  164: =item 4. Australian state code or name via Locale::AU
  165: 
  166: =item 5. Locale::Object::Country by name
  167: 
  168: =item 6. Geo::GeoNames search (optional, only if object provided at
  169: construction)
  170: 
  171: =item 7. Unknown - returns with C<unknown =E<gt> 1>
  172: 
  173: =back
  174: 
  175: =head1 TODO
  176: 
  177: =over 4
  178: 
  179: =item * Add C<normalise_place()> to handle missing commas before
  180: country and state names in raw uncleaned input strings. Poor data
  181: import means strings like C<"Houston TX USA"> or
  182: C<"Some Place England"> need comma insertion before component
  183: extraction can work correctly. This should be implemented before
  184: relying on C<resolve()> for raw uncleaned input.

  186: =back

  285: =head2 resolve
  286: 
  287: =head3 Purpose
  288: 
  289: Resolves the last comma-separated component of a place string to a
  290: canonical country name, and returns the (possibly modified) place
  291: string alongside any warnings generated during resolution.
  292: 
  293: =head3 API Specification
  294: 
  295: =head4 Input
  296: 
  297:     {
  298:         component => { type => 'string', min => 1 },
  299:         place     => { type => 'string', min => 1 },
  300:     }
  301: 
  302: =head4 Output
  303: 
  304:     {
  305:         type   => 'hashref',
  306:         schema => {
  307:             country  => { type => 'string',   optional => 1 },
  308:             place    => { type => 'string',   min => 1 },
  309:             warnings => { type => 'arrayref' },
  310:             unknown  => { type => 'boolean' },
  311:         },
  312:     }
  313: 
  314: =head3 Arguments
  315: 
  316: =over 4
  317: 
  318: =item * C<component> - The last comma-separated component of the place
  319: string, e.g. C<"England">, C<"TX">, C<"NSW">. Required.
  320: 
  321: =item * C<place> - The full place string, e.g.
  322: C<"Ramsgate, Kent, England">. May be modified by appending a country
  323: suffix where needed. Required.
  324: 
  325: =back
  326: 
  327: =head3 Returns
  328: 
  329: A hashref containing:
  330: 
  331: =over 4
  332: 
  333: =item * C<country> - The canonical country name as a string, e.g.
  334: C<"United Kingdom">. C<undef> if resolution failed.
  335: 
  336: =item * C<place> - The full place string, possibly with a country
  337: suffix appended (e.g. C<", USA">). Always returned even if unmodified.
  338: 
  339: =item * C<warnings> - An arrayref of warning strings generated during
  340: resolution. May be empty. The caller is responsible for acting on
  341: these, e.g. by passing them to a C<complain()> function.
  342: 
  343: =item * C<unknown> - A boolean. True if the country could not be
  344: resolved by any method.
  345: 
  346: =back
  347: 
  348: =head3 Side Effects
  349: 
  350: None. All warnings are returned to the caller rather than emitted
  351: directly.
  352: 
  353: =head3 Notes
  354: 
  355: Resolution order is: direct lookup, US state, Canadian province,
  356: Australian state, Locale::Object::Country, GeoNames (if available).
  357: The first successful match wins.
  358: 
  359: When a US state, Canadian province, or Australian state is recognised,
  360: the appropriate country string (C<", USA">, C<", Canada">,
  361: C<", Australia">) is appended to C<place> if not already present.
  362: 
  363: =head3 Example
  364: 
  365:     my $result = $resolver->resolve(
  366:         component => 'TX',
  367:         place     => 'Houston, TX',
  368:     );
  369: 
  370:     # $result->{country}     eq 'United States'
  371:     # $result->{place}       eq 'Houston, TX, USA'
  372:     # $result->{warnings}[0] eq 'TX: assuming country is United States'
  373:     # $result->{unknown}     is 0
  374: 
  375: =cut

  580: =head1 BUGS
  581: 
  582: =over 4
  583: 
  584: =item * The direct lookup table contains C<nl> as an abbreviation for the
  585: Netherlands.  This conflicts with C<NL>, the ISO 3166-2 code for the Canadian
  586: province of Newfoundland and Labrador.  Because the direct table is consulted
  587: before the C<Locale::CA> province-code path, passing C<component =E<gt> 'NL'>
  588: currently resolves to C<Netherlands> rather than C<Canada>.  The workaround
  589: is to pass the full province name (C<Newfoundland and Labrador>) or to ensure
  590: the place string includes an explicit C<Canada> suffix before calling
  591: C<resolve()>.
  592: 
  593: =item * C<Geo::GeoNames> generates its query methods via C<AUTOLOAD>, so
  594: C<can('search')> returns false at the Perl level even though
  595: C<$geonames-E<gt>search(...)> works correctly at runtime.  The constructor
  596: schema currently validates the optional C<geonames> argument with
  597: C<can =E<gt> 'search'>, which rejects a real C<Geo::GeoNames> object.
  598: Until this is resolved, pass a wrapper object that defines C<search> as a
  599: named method, or subclass C<Geo::GeoNames> and add a stub:
  600: 
  601:     package My::GeoNames;
  602:     use parent 'Geo::GeoNames';
  603:     sub search { my $self = shift; $self->SUPER::search(@_) }
  604: 
  605: =back
