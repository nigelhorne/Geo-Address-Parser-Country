  143: =head1 DESCRIPTION
  144: 
  145: Resolves the last comma-separated component of a place string into a
  146: canonical country name. Handles common variants, abbreviations, and
  147: historical names found in genealogy data and other poorly-normalised
  148: address sources.
  149: 
  150: Designed specifically to tolerate poor-quality data from software
  151: imports where place strings may be inconsistent, abbreviated, or use
  152: historical country names no longer in common use.
  153: 
  154: Resolution proceeds through the following steps in order:
  155: 
  156: =over 4
  157: 
  158: =item 1. Direct lookup table (covers historical names, abbreviations,
  159: common variants)
  160: 
  161: =item 2. US state code or name via Locale::US
  162: 
  163: =item 3. Canadian province code or name via Locale::CA (English and French)
  164: 
  165: =item 4. Australian state code or name via Locale::AU
  166: 
  167: =item 5. Locale::Object::Country by name
  168: 
  169: =item 6. Geo::GeoNames search (optional, only if object provided at
  170: construction)
  171: 
  172: =item 7. Unknown - returns with C<unknown =E<gt> 1>
  173: 
  174: =back
  175: 
  176: =head1 TODO
  177: 
  178: =over 4
  179: 
  180: =item * Add C<normalise_place()> to handle missing commas before
  181: country and state names in raw uncleaned input strings. Poor data
  182: import means strings like C<"Houston TX USA"> or
  183: C<"Some Place England"> need comma insertion before component
  184: extraction can work correctly. This should be implemented before
  185: relying on C<resolve()> for raw uncleaned input.

  187: =back

  286: =head2 resolve
  287: 
  288: =head3 Purpose
  289: 
  290: Resolves the last comma-separated component of a place string to a
  291: canonical country name, and returns the (possibly modified) place
  292: string alongside any warnings generated during resolution.
  293: 
  294: =head3 API Specification
  295: 
  296: =head4 Input
  297: 
  298:     {
  299:         component => { type => 'string', min => 1 },
  300:         place     => { type => 'string', min => 1 },
  301:     }
  302: 
  303: =head4 Output
  304: 
  305:     {
  306:         type   => 'hashref',
  307:         schema => {
  308:             country  => { type => 'string',   optional => 1 },
  309:             place    => { type => 'string',   min => 1 },
  310:             warnings => { type => 'arrayref' },
  311:             unknown  => { type => 'boolean' },
  312:         },
  313:     }
  314: 
  315: =head3 Arguments
  316: 
  317: =over 4
  318: 
  319: =item * C<component> - The last comma-separated component of the place
  320: string, e.g. C<"England">, C<"TX">, C<"NSW">. Required.
  321: 
  322: =item * C<place> - The full place string, e.g.
  323: C<"Ramsgate, Kent, England">. May be modified by appending a country
  324: suffix where needed. Required.
  325: 
  326: =back
  327: 
  328: =head3 Returns
  329: 
  330: A hashref containing:
  331: 
  332: =over 4
  333: 
  334: =item * C<country> - The canonical country name as a string, e.g.
  335: C<"United Kingdom">. C<undef> if resolution failed.
  336: 
  337: =item * C<place> - The full place string, possibly with a country
  338: suffix appended (e.g. C<", USA">). Always returned even if unmodified.
  339: 
  340: =item * C<warnings> - An arrayref of warning strings generated during
  341: resolution. May be empty. The caller is responsible for acting on
  342: these, e.g. by passing them to a C<complain()> function.
  343: 
  344: =item * C<unknown> - A boolean. True if the country could not be
  345: resolved by any method.
  346: 
  347: =back
  348: 
  349: =head3 Side Effects
  350: 
  351: None. All warnings are returned to the caller rather than emitted
  352: directly.
  353: 
  354: =head3 Notes
  355: 
  356: Resolution order is: direct lookup, US state, Canadian province,
  357: Australian state, Locale::Object::Country, GeoNames (if available).
  358: The first successful match wins.
  359: 
  360: When a US state, Canadian province, or Australian state is recognised,
  361: the appropriate country string (C<", USA">, C<", Canada">,
  362: C<", Australia">) is appended to C<place> if not already present.
  363: 
  364: =head3 Example
  365: 
  366:     my $result = $resolver->resolve(
  367:         component => 'TX',
  368:         place     => 'Houston, TX',
  369:     );
  370: 
  371:     # $result->{country}     eq 'United States'
  372:     # $result->{place}       eq 'Houston, TX, USA'
  373:     # $result->{warnings}[0] eq 'TX: assuming country is United States'
  374:     # $result->{unknown}     is 0
  375: 
  376: =cut

  581: =head1 BUGS
  582: 
  583: =over 4
  584: 
  585: =item * The direct lookup table contains C<nl> as an abbreviation for the
  586: Netherlands.  This conflicts with C<NL>, the ISO 3166-2 code for the Canadian
  587: province of Newfoundland and Labrador.  Because the direct table is consulted
  588: before the C<Locale::CA> province-code path, passing C<component =E<gt> 'NL'>
  589: currently resolves to C<Netherlands> rather than C<Canada>.  The workaround
  590: is to pass the full province name (C<Newfoundland and Labrador>) or to ensure
  591: the place string includes an explicit C<Canada> suffix before calling
  592: C<resolve()>.
  593: 
  594: =item * C<Geo::GeoNames> generates its query methods via C<AUTOLOAD>, so
  595: C<can('search')> returns false at the Perl level even though
  596: C<$geonames-E<gt>search(...)> works correctly at runtime.  The constructor
  597: schema currently validates the optional C<geonames> argument with
  598: C<can =E<gt> 'search'>, which rejects a real C<Geo::GeoNames> object.
  599: Until this is resolved, pass a wrapper object that defines C<search> as a
  600: named method, or subclass C<Geo::GeoNames> and add a stub:
  601: 
  602:     package My::GeoNames;
  603:     use parent 'Geo::GeoNames';
  604:     sub search { my $self = shift; $self->SUPER::search(@_) }
  605: 
  606: =back
